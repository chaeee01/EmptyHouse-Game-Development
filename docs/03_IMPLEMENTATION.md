### 3) 기존 시스템과 연결한 방법
- **감지**: 기존 감지 수집 결과를 훅②에서 걸러, 추격 전 단계에서는 "시야 안 + 달리기"만 통과(바닥 의심도 100 + 타겟). 달리지 않으면 시각·근접 자극을 지운다. 경고·추격 중에는 손대지 않아 기존 추격 규칙이 그대로 적용된다.
- **경고**: 기존 "발각 전환" 상태를 Teacher 전용 경고 상태로 교체(훅③). 복제되는 상태 종류는 그대로라 클라이언트 연출(포효 애니메이션·음성)과 위협 음악 연동이 기존 경로로 동작한다.
- **취소**: 기존 진정 처리로 타겟·래치·의심도를 비운 뒤 순찰로 전이. 래치 해제·타겟 id 0 → 클라이언트 위협 음악 해제(기존 위협 연출 판정 경로).
- **달리기 판정**: 플레이어 이동 컴포넌트의 달리기 복제값(오너 권위)을 감지 인터페이스로 노출. 서버에서 읽는다.
- **프리팹**: Walker 프리팹을 복제한 독립 원본에서 컨트롤러 컴포넌트의 스크립트만 교체해, 같은 오브젝트의 공통 컴포넌트 5개가 가진 컨트롤러 참조를 끊지 않고 유지.

### 3) 기존 시스템과 연결한 방법
- **비명 = 기존 소음 이벤트**: 서버가 단발 채널로 소음 이벤트를 1회 발행한다. 전파·차폐·가청 판정과 다른 좀비의 "소리 난 곳 조사"는 전부 기존 코드가 한다. 소음원이 플레이어가 아니라 듣는 좀비는 타겟을 잡지 않고 위치만 조사한다.
- **예고 = 발각 전환 교체**: Teacher 와 같은 방식. 클라이언트 연출(포효 애니메이션·음성)은 기존 복제 경로로 재생되고, 예고 취소 시 작업 1-2 의 포효 중단을 옵트인했다.
- **경직·기절 취소**: 코어가 전투 중단 동안 상태 Tick 을 멈추고 회복 시 다른 상태로 전이하므로 예고 상태가 비명 단계에 도달하지 못한다. 규칙에도 무력화 입력을 명시해 테스트로 고정했다.
- **쿨다운 중 즉시 도주**: 발각 전환을 거치지 않고 상태 머신으로 바로 도주 — 예고 연출이 한 순간이라도 재생되지 않게 한다.
- **자기 비명 무시**: 청각을 끈 프로파일로 처리(소음 전파는 소음원 자신도 후보로 훑는다).

### 4) 직접 구현한 코드·설정
- 예고 판정 우선순위: 이미 비명 → 경직·기절 → 타겟 소실 → 시야 상실(유예) → 완료(비명). 비명은 한 예고 시계에서 단 1회만 반환된다.
- 도주: 위협 반대 방향 중심 8방향 후보 → 위협 쪽 후보 제거 → NavMesh 스냅 → "멀어진 거리 + 정렬 가산" 최고점. 3초간 못 보면 위협 망각 → 진정 → 귀가.
